## 3) إزاي التحديثات بتتعمل (الطريقة الحالية)

### تعديل في الشاشات بس
1. Claude بيعدّل ويجرّب ويرفع على GitHub (dev وmain).
2. **شاشة السيرفر:**
   ```bash
   sudo bash /opt/motionpos/repo/tools/motionpos_server.sh update && sudo git -c safe.directory='*' -C /opt/motionpos/repo log -1 --format=%h
   ```
3. **شاشة اللابتوب:**
   ```powershell
   if ($env:USERNAME -ne 'MotionDev') { 'الجهاز ده مش لابتوب المحل ❌' } else {
   $shop = 'D:\SmartPOS'; $tool = 'D:\MotionLocal\tools\motionlocal.ps1'
   git -C $shop fetch -q origin; git -C $shop merge --ff-only origin/dev
   "نسخة المحل: " + (git -C $shop rev-parse --short HEAD)
   powershell -ExecutionPolicy Bypass -File $tool -Step update }
   ```
4. **Ctrl + F5** على كل الأجهزة.

### ملف قاعدة جديد (0XX)

**قواعد كتابة الملف:**
- begin وcommit، وفحص الترميز (`length('إكراميات') <> 8`)، وحارس الإصدار (يقبل اللي قبله أو نفسه).
- الدوال بتتنسخ من آخر ملف معرّفها بالظبط، والتعديل بس هو اللي بيتغيّر.
- رفع الإصدار في `motionpos_version_public`، وحلقة الصلاحيات (grants loop).
- اختبار داخلي بيتراجع وبيطبع `MOTIONPOS-0XX-SELFTEST-OK`.
- `notify pgrst, 'reload schema'` قبل commit.

**في الأداة:** بصمة الملف بتتضاف في `$Files` جوه tools/motionlocal.ps1، و`$LastVersion` بيتغيّر. البصمة = أول 16 حرف من sha256 للملف بعد شيل `\r`.

**التجربة:** على قاعدة تجربة كاملة، بالباك أب schema_2026-10-06 وكل الملفات من 001. ولازم الأدوار (owner, branch_manager, cashier, waiter, storekeeper) تتضاف في جدول roles قبل الملفات.

**النشر:**
- **السيرفر** (الملف بيتشغل كله أو مايتشغلش خالص):
  ```bash
  sudo bash .../motionpos_server.sh update
  ```
  وبعدين pg_dump كنسخة احتياطي، وبعدين:
  ```bash
  sudo bash .../motionpos_server.sh sql /opt/motionpos/repo/supabase/migrations/0XX_....sql
  ```
- **اللابتوب** بعد السيرفر:
  - pause.
  - git merge.
  - psql -f للملف.
  - التأكد من الإصدار.
  - نسخ الأداة لـ D:\MotionLocal\tools (بعد نسخة .bak).
  - update، وبعدين resume.
  - إعادة تشغيل التاسك «MotionPOS Shop Server».
  - status.

### تغيير بيانات بس (من غير ملف قاعدة)
بيتعمل على السيرفر بس، والمزامنة بتوصّله للابتوب، والمزامنة شغالة عادي. لازم UUID ثابتة (uuid5) لأي حاجة جديدة، وحارس يمنع التكرار، ونسخة احتياطي قبلها.

### دروس اتعلمناها
- المزامنة ماترجعش إلا بعد ما ملف القاعدة يتطبق على الجهازين.
- جدول warehouse_stock مش بيتزامن، وكل جهاز بيحسبه من stock_movements. علشان كده `-Step compare` بيبيّن دايماً فرق شكلي فيه.
- `motionpos.sync_apply='on'` بيوقّف تسجيل المزامنة، و`motionpos.system_reset='on'` بيعدّي أقفال المسح.
- أداة اللابتوب مابتتنسخش مع update، ولازم تتنسخ بالإيد.

## 5) اليوم العادي في المحل (بعد آخر التعديلات)

1. **يوم الشغل من 8 الصبح لـ 8 الصبح اللي بعده.** المحل بيفتح 8 الصبح وبيقفل 7 الصبح، والتقارير ولوحة المتابعة بتحسب اليوم كده. الإعداد في الإعدادات ← الشركة ← «يوم الشغل بيبدأ الساعة»، وهو 8.
2. **الحضور:** كل موظف لازم **يفتح البرنامج بحسابه هو** ويكتب رقمه السري في شاشة الوردية. رقم موظف تاني بيترفض برسالة «الرقم السري ده مش بتاعك».
3. **الوردية:** **وردية واحدة بس مفتوحة في الفرع.** لو حد حاول يفتح وردية تانية، بتطلعله رسالة فيها اسم صاحب الوردية المفتوحة.
4. **الطلبات والدفع:** زي الأول.
   - زرار «مرتجع طلب مدفوع» **اتشال** من شاشة البيع، والدالة نفسها لسه موجودة في الكود.
   - **إلغاء الطلب** فيه خانة «الإلغاء غلطة موظف؟». لو اتختار موظف، الطلب بيتحسب هالك، و**تكلفة الخامات بس** بتتخصم منه، مش سعر البيع. القيد: مدين 1130 ذمم الموظفين، ودائن 5100. وبيتسجل على حسابه كعجز، فبيتخصم من المرتب.
5. **البيوريهات:** إضافة ببلاش اسمها «تحسين الطعم (بيوريه)» على العصير الفريش والسموذي والميلك شيك والكوكتيلات. الكاشير يختارها لما الباريستا يحط بيوريه، فتتخصم 20 مل من المخزن من غير ما الفاتورة تزيد.
6. **الضيافة:** زرار 🎁 في شاشة الدفع.
   - القيد بالتكلفة: ضيف المالك والموظفين على 6600، والأهل على 3300، والدعاية على 6300.
   - المدير يوافق لحد 500 جنيه في اليوم.
   - التقرير في التقارير ← الضيافة.
7. **قفل الوردية وتقفيل اليوم:** زي الأول.
